# M07 — Journey, accessibility and technical review

Date: 2026-11-10. Baseline: M06 `62ec535`; clean main, existing history and locked dependencies verified. The initial Vitest run passed all 220 existing tests. This review uses Chromium and M01-based intercepted responses; it is not live service evidence.

## Findings and focused repairs

- **Confirmed mutation race:** start add A, navigate and confirm newer add B, then receive A. The old implementation replaced B's count with A's late response. A new regression failed before the repair. CartProvider now numbers initiated adds and remembers the newest *valid confirmation*. Older replies cannot replace that confirmation in state/storage. A failed newer add does not discard an older valid response. The numbers order requests; they never manufacture cart totals. Two RTL cases and a browser journey protect both outcomes. Pending/double-submit protection remains local to the form; no queue, retry, proxy or session substitute was introduced.
- **Confirmed image overflow:** at 375/480 px a detail image could exceed its fixed-height grid area and approach/overlap the summary. Explicit shrinkable grid tracks now constrain the image without cropping it. Browser geometry checks cover those intermediate widths as well as existing mobile/desktop projects. No replacement photo assets were added.
- **Announcements:** Header count changes now use polite, atomic announcement markup, including confirmations received after leaving PDP. The local success message uses plain Spanish product/count feedback. Keyboard skip-link, visible focus, named fieldsets and eleven semantic term/definition pairs have a focused browser check.
- **Recovery:** the existing failed-POST browser case now exercises an explicit successful resubmission, preserving selections and replacing the count exactly. Existing read retry, history, direct entry, refresh, missing-price/image and incomplete/duplicate submission cases are retained rather than duplicated.

## Visual and accessibility inspection

Catalogue and detail captures were generated and visually inspected at 320, 375, 480, 768, 1280 and 1920 CSS px. Grid columns were respectively 1/1/2/3/4/4; cards align within rows, while row heights may grow for longer names. Search sits above/right of the desktop grid and spans the mobile content. Detail is image-left/information-right from 768 px and image-first stacked below it; actions follow the eleven attributes. Header/breadcrumbs/count remain consistent. Final image bounds match their frames; no horizontal document overflow or unhandled page errors was observed in these mocked journeys.

The PDF's list/detail wireframes (pp.3–4) were rendered and inspected. Styling remains free; the required structure is preserved. Captures use the existing synthetic **test-only** image, or the existing missing-image fallback, and stay outside Git. They do not establish current remote photo availability.

Native browser zoom was set to 200% in a temporary Chromium profile using a temporary diagnostic extension outside the repository. `chrome.tabs.getZoom` returned 2; a 1280 px window had 640 CSS px viewport and devicePixelRatio 2. No document overflow was observed on either route. No application dependency, extension or browser preference is installed for the user.

Manual/DOM review covers one h1 per view, logical h2 regions, dl/dt/dd specifications, labeled search, native radio fieldsets/legends, Tab/Shift-Tab and Enter/Space/arrow behavior, skip navigation, visible focus, result statuses and cart/error feedback. Measured text/focus palette contrast on the relevant white/light surfaces ranges from 5.47:1 to 16.45:1 (selected-control blue 6.98:1); this is a scoped palette check, not a WCAG certification. A human assistive-technology pass and other browser engines remain outside the verified coverage.
